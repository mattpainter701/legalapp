# Research quality acceptance

This is a bounded launch acceptance workflow, not a replacement or parity claim for an established research service. No customer jurisdiction/practice was supplied. The committed questions and outputs are fictional, deterministic contract fixtures; they contain no attorney ground truth. No live corpus, provider costs or research quality was measured in development.

## Serving behavior and compatibility

Public research still uses existing lexical/semantic relevance gates, promoted source admission, coverage reporting, source-linked citation annotations and treatment-review contracts. A scoped result now must carry matching source metadata before it can fill a requested jurisdiction. Authority catalogue codes (ND, CA, US) and CourtListener court IDs/category F are different vocabularies: a state court ID can verify its exact requested court; category F verifies a separately requested federal search. A court category S alone does not identify a state. Missing, malformed or mismatched metadata is excluded from the scoped result, with the jurisdiction remaining missing. An HTTP 200 with insufficient metadata remains successful transport with incomplete evidence, not an outage. Unscoped searches retain their sources with unknown metadata.

Deploy the research sidecar candidate before or with the backend. Caselaw FTS and hybrid responses now include the existing court jurisdiction column alongside court_id; no migration is needed. Older sidecars already return state court IDs and authority jurisdiction. Older federal responses without the category field will conservatively leave federal coverage missing until upgraded. Rehearse both sidecar versions. Backend and frontend add optional metadata; old stored citations render unknown dates/status. Source cards display raw CourtListener category codes as source metadata, alongside the court name; those codes do not assert a controlling-law conclusion.

Catalogue document status, retrieval/sync dates, termination dates and relevance are not evidence that a proposition is current law. Public prompts explicitly retain that distinction; citation cards say treatment/current law require review. The change does not add a licensed citator, infer good law, validate a model's entire answer, or suppress supported findings merely because other claims need review.

## Offline evaluator

From the repository root, with Python and `PYTHONPATH=backend`:

```powershell
$env:PYTHONPATH = 'backend'
python -m app.research_quality backend/tests/fixtures/research_quality/synthetic-set.json backend/tests/fixtures/research_quality/synthetic-run.json --output research-report.json
```

The module is standard-library-only, opens only supplied local JSON files and writes the named report. It does not query databases, call providers, ingest material, send messages or activate features. Exit 0 means this evidence contract passed; exit 1 means rejected/incomplete. Invalid schemas/thresholds fail execution. The synthetic example deliberately returns 1 even if all mechanical checks pass. Output includes dataset/run digests, per-question failures, authority recall and observation digests for review.

Start with the example schema, then have the customer's attorney approve 20–30 representative questions before collecting outputs. This is an initial acceptance set, not a statistically sufficient competitive benchmark. Include the firm's day-one jurisdictions/practices, questions with more than one jurisdiction, controlling and persuasive sources, missing corpus, unavailable source, irrelevant high-similarity retrieval, historic/expired law, ambiguous questions and correct abstention. Populate stable `expected_authorities`, `expected_propositions`, `allowed_jurisdictions`, `must_abstain` and `required_gaps`; determine authority relevance and controlling status with the attorney, not an LLM. Set `min_authority_recall` (greater than zero, at most 1), `max_latency_ms`, and `max_cost_usd` before running. Every case must meet the thresholds; averages cannot hide a failed case.

Set `evidence_kind: attorney_defined`, `approved_by`, and `approved_at` only for a genuinely reviewed set. Run observations use `evidence_kind: customer_capture` only for actual captured application results. The scorer cannot authenticate a person from a JSON file: store the dataset, raw output, review and report in the approved access-controlled evidence location with accountable sign-off. Labels and checksums are provenance aids, not digital signatures.

## Candidate and capture checklist

1. Choose the exact backend/frontend and sidecar SHAs, tenant, matter scope, model/routing settings, retrieval limits and run time. Use permissioned representative matter context; redact identifiers before exporting where appropriate. Keep credentials and restricted material out of Git and public logs.
2. Record the promoted corpus version, manifest digest, as-of timestamp and immutable location/digest of the `authority_coverage` projection. Record its source partitions, admission/rights decisions, freshness, exclusions, failed or pending sources, and current treatment coverage. A large corpus count is not completeness. Never ingest unlicensed content to improve the score.
3. Capture each question through the real matter research/chat journey on the candidate. Retain complete answer text and citation annotations, retrieved source IDs/content/URLs, actual source jurisdictions, source versions and source capture dates. Preserve the raw response separately; do not substitute expected answers. Record end-to-end latency and measured provider cost including retries; unavailable cost is null and fails, not zero. Capture consented provider usage only through the normal application route. The offline evaluator has no live-run switch.
4. Normalize each response into `observations`: stable case `id`, `answer`, `sources` with `id`, `authority_id`, `jurisdiction`, `url`, `content`, `currentness`; all substantive `claims` with `id`, `source_ids`, and optional `quotes` (`source_id`, exact `text`); `abstained`, `disclosed_gaps`, `latency_ms`, `cost_usd`. This normalization is operator-reviewed against raw output; omitting an unsupported claim would invalidate acceptance. Mark `asserts_current_law` on claims making that assertion. `currentness` stays unknown/stale unless an attorney actually verifies it for this run. Disclose `currentness_not_established` for unverified sources. Similarity or a `current` catalogue row must never populate `attorney_verified`.
5. Run the evaluator before review. Give the attorney the raw answers, every source/quotation, expected authorities and known corpus gaps, including unsupported extra claims. Exact quote containment and citation resolution are mechanical checks; they cannot establish proposition support, completeness, controlling law or treatment.
6. For each question, save a review in `reviews[case_id]` with `reviewer`, `reviewed_at`, and the reported `observation_digest`. Explicitly grade `jurisdiction_correct`, `proposition_support`, `treatment_currentness`, `uncertainty_appropriate`, `answer_complete` as booleans. Supply `supported_propositions` covering the expected proposition IDs and `supported_claims` covering every actual claim ID. A correct abstention can pass human review without fabricated sources. Any changed answer/source/latency/cost changes its digest and requires review again. Unknown, missing, false or stale review evidence fails.
7. Re-run, inspect every failure and retain the report together with original evidence. Acceptance requires a nonempty approved set, exactly one observation per question, identified corpus/candidate, all hard checks and all attorney reviews. Have the customer explicitly approve residual coverage limits and continued use of authoritative verification tools. Re-run affected questions after corpus, model, serving or treatment changes; do not carry an old acceptance to a new candidate.

## Development validation boundary

`test_research_quality.py` exercises fail-closed evaluation, malformed thresholds, quote integrity, missing sources, unknown jurisdiction/currentness, stale review digests, outages/abstention, latency/cost and the synthetic/customer separation. `test_rag_mcp.py` calls real mapping, relevance filtering, jurisdiction accounting, context and citation serialization with mocked transport. It includes mixed federal/state results where the federal result remains useful and a missing state remains disclosed. Source-card tests verify date/status visibility and honest unknowns. These are regression tests, not real retrieval recall measurements or attorney judgments. PostgreSQL execution of sidecar FTS/hybrid remains in its existing authority rehearsal CI; do not describe SQL contract mocks as a live corpus run.
